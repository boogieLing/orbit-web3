# Orbit 应用创作

入口：站点「创作应用」或 `/studio`。核心业务由 Go 实现，原生 SQLite 与线上 Worker/D1 共用同一套服务。

## 操作路径

1. 新建应用，填写名称和具体功能，点击「开始创作」。
2. 服务端保存需求和任务后调用 DeepSeek；成功后预览可实际操作的 HTML 应用。失败会保留记录和原版本，不自动重新调用。
3. 在对话区继续描述功能或样式修改。当前代码与当前版本祖先需求作为上下文，返回完整新文件。
4. 项目、需求记录和代码版本在服务端保存。刷新后恢复当前项目；通过版本历史查看与恢复旧代码。
5. 应用内 localStorage 经隔离存储桥保存为项目业务数据。代码回退保留业务数据；多页面冲突会停止覆盖并提示重新读取。
6. 「源码」查看文件；下载按钮导出当前应用。下载文件可本地独立运行，业务数据不随源码导出。

## 服务与执行边界

配置名见 `.env.example`，配置值通过服务端环境提供。DeepSeek 使用结构化文件返回；不完整输出、外部资源、超大文件和上游失败不能推进成功版本。任务原子领取、幂等键及 revision 保护重复请求和并发覆盖。数据库事务不跨外部调用。

预览为 `sandbox=allow-scripts` 的无同源 iframe，前置 CSP 禁止网络、表单外发与外部资源。父窗口校验消息来源、opaque origin、随机通道和数据容量。文件上限 256 KiB；业务数据上限 32 KiB、100 个键；每条需求 2–2000 字。

当前支持单文件客户端工具，不安装依赖、不执行服务器代码、不进行链上交易。会话身份丢失后，匿名项目不能自动找回；应在同一浏览器内验收，连接身份的后续扩展不作为当前交付能力。

## 工程取舍

- 任务先保存再执行；刷新后可继续尚未执行的任务。已执行任务不会自动重发，超时由项目读取收敛。
- 版本只追加，恢复移动当前指针。后续修改沿所选版本祖先取上下文，完整对话仍保留其他分支记录。
- 本实现采用整文件迭代，要求模型保留原有行为与存储键；语义正确性仍通过实际操作验收，不对任意需求宣称无回归。
- 在线额度由站点服务端统一管理，访客不能更换密钥或自定义调用目标。
