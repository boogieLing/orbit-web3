# 部署说明

## Sites

项目身份保存在 `.openai/hosting.json`。保留现有 project_id，不能为重试重复创建站点。逻辑数据库绑定名为 `DB`，部署时由平台供应并在上传 Worker 前应用迁移。

发布步骤：

1. 校验 TypeScript、Go 核心与实际 Worker API。
2. 使用 Sites source helper，输入同一站点的短期仓库凭据，运行官方 build-site.mjs，提交并推送精确源码，生成部署归档。
3. 使用返回的 project_id、commit_sha、archive 保存并部署；已保存版本的重试只部署该版本。
4. 部署成功后对实际站点 URL 执行业务验收，确认 D1 写入与独立请求读回。

凭据只经隐藏标准输入传递，不放进参数、日志或文件。归档不包含 .env、运行数据库、原题、附件或本地工作记录。平台默认访问范围为站点所有者；改变分享范围需要单独明确设置。

## 环境变量

线上环境使用 Sites 变量管理。`USEDIT_EXPERIENCE_MODE` 默认启用，提供内容库、社区身份、交互记录与本地页面调整；不需要额外服务或密钥。显式设为 `false` 才使用钱包与外部服务路径。`ETH_RPC_URL` 为服务器发起的 HTTP RPC；可选 `COMPOSE_URL`、`COMPOSE_API_KEY`、`COMPOSE_MODEL` 仅用于受约束的页面调整。不要把密钥设置为前端公开变量。

本地开发需要的 Worker 变量放在被忽略的 `.dev.vars`；原生 API 从进程环境读取。两种服务分别使用 D1 本地状态和 SQLite 文件，不会自动互相同步数据。

## 恢复与兼容

迁移一旦成功应用即不可改写，后续变更追加新文件。发布失败可能已经应用数据库迁移，因此先核对状态再决定修复。页面与 API 使用 `/api/v1` 合同；旧页面遇到版本冲突必须重新读取，不应覆盖较新的内容。

回退部署使用已保存且兼容当前数据库结构的版本。首版没有历史线上版本可回退，源码提交与归档为后续恢复依据。
